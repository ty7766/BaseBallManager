# 🎨 디자인 요청서 — Desktop ↔ CLI 분업 명세

> **용도**: Claude Desktop(디자인)과 Claude Code CLI(구현) 사이의 작업 계약서.
> 화면은 **이미 전부 구현되어 동작**한다. 이 문서는 "어느 화면에 어떤 애셋을 끼우면 더 좋아지는가"를
> 화면별로 적어 둔 것이고, 애셋이 없어도 코드 기본 도형으로 떨어지므로 게임은 굴러간다.
>
> 경기 화면 4장의 **확정 디자인**은 `경기_UI_명세.md` 6장이다. 이 문서는 그 밖의 화면을 다룬다.

---

## 0. 분업 규칙

| 단계 | 담당 | 산출물 |
| --- | --- | --- |
| ① 시안 | **Desktop** | 캔버스 보드 (1080×1920 좌표 그대로) |
| ② 확정 | 작성자 | 보드 승인 → `경기_UI_명세.md` 6장처럼 토큰·좌표로 문서화 |
| ③ 렌더 | **Desktop** | `Design/ui_assets/render_assets.py` (SVG → 헤드리스 Edge, 투명 PNG) + `manifest.json` |
| ④ 임포트 | **CLI** | `Assets/Resources/UI/**`로 이동 + `manifest.json` 규격을 `.meta`에 기록 |
| ⑤ 구현 | **CLI** | `Assets/Scripts/UI/**` — 좌표 1:1로 코드 조립 |
| ⑥ 검증 | **CLI** | 하니스 PASS/FAIL (Unity 없이 컴파일 + 데이터 경로) |

**애셋 규격**은 `경기_UI_명세.md` 3장(납품 규격) · 3-1(목록) · 3-3(실제 로고)을 따른다.
흰색 기준으로 그리고 런타임에 틴트하는 원칙은 그대로다.

**CLI가 애셋 없이도 깨지지 않게 만든 규칙**
`UiSprites.Get()`이 없는 경로에 null을 돌려주고, `Image`는 스프라이트 없이 **단색 사각형**으로 남는다.
그래서 PNG를 나중에 넣어도 코드를 고칠 필요가 없다. 파일만 떨어뜨리면 그 자리에 들어간다.

## 1. 🔒 작성자가 할 3가지

| # | 할 일 | 위치 | 없을 때 동작 |
| --- | --- | --- | --- |
| 1 | **실제 구단 로고 10종** | `Assets/Resources/UI/Team/logo_<팀명>.png` | 팀 컬러 판 + 이니셜로 대체 (명세 3-3) |
| 2 | **선수 CSV 업데이트** (시그·골글 추가) | `Assets/Resources/Data/HitterCards.csv` · `PitcherCards.csv` | 시그 뽑기 빈 결과 · 골글 제작 실패 · `StatBaseline` 드리프트 유지 |
| 3 | **누끼 사진** | `Assets/Resources/Photos/<photoKey>.png` (768×960) | 카드 상세의 사진 자리가 비어 있음 (카드는 정상 표시) |

- 로고·사진은 **공개 저장소라 커밋되지 않는다** (`.gitignore`). 로컬·별도 백업으로 보관한다.
- CSV `photo` 열은 **선택**이다. 비어 있으면 사진 없는 카드로 그려진다.
- 사진 파이프라인: `PhotoPipeline/build_photos.py` (YuNet 눈·입 검출 → BiRefNet 누끼 → 768×960 + `review.html`).

## 2-6. 연출 (세션 54 구현 완료)

연출은 전부 **UI 네이티브 트윈 + 파티클**로 돌아간다. 상세 목록은 `PROGRESS.md` 2-8.

| 요청 가능한 것 | 방법 |
| --- | --- |
| **파티클 모양 교체** | `Assets/Resources/UI/Fx/spark.png` · `star.png` · `confetti.png`를 같은 이름으로 덮어쓴다. **흰색 기준**으로 그리면 프리셋 색으로 틴트된다 |
| 새 파티클 종류 추가 | `UiEffectKind` + `UiParticleSettings.Get` 프리셋 1개 추가 (CLI 작업) |
| 스피너 교체 | `Common/spinner_00~07` 8프레임을 덮어쓴다 |
| 연출 세기·속도 조정 | 프리셋 수치(개수 · 속도 · 중력 · 수명)만 바꾸면 된다 |

🔴 **Unity ParticleSystem / VFX Graph / 에셋스토어 파티클 프리팹을 쓰려면** 캔버스를
`ScreenSpaceOverlay` → `ScreenSpaceCamera`로 바꾸고 전용 카메라를 세워야 한다 (Overlay 캔버스 위로는
월드 렌더러가 그려지지 않는다). 지금 구조에서는 UI 네이티브 파티클이 같은 역할을 하고 있으니,
정말 필요해질 때 작성자 확인 후 전환한다.

## 3. 코드가 이미 받아들일 준비가 된 애셋

파일만 넣으면 **코드 수정 없이** 반영된다. 경로는 `Assets/Resources/UI/` 기준.

| 경로 | 쓰이는 곳 | 현재 대체 |
| --- | --- | --- |
| `Team/logo_<팀명>` | 경기 전 대진 · 카드 앞면 · 팀 선택 | 팀 컬러 + 이니셜 |
| `Card/card_base_normal` · `_signature` · `_goldenglove` | 카드 앞면·뒷면 베이스 (1398×1957) | 팀색 반투명 패널 |
| `Card/card_mask_photo` · `card_team_aura` · `card_name_shadow` | 카드 사진 주변 레이어 | 투명(없는 레이어) |
| `Card/card_fx_shine_5` · `card_fx_glow_signature` · `_goldenglove` | 5성·시그·골글 광택 | 숨김 |
| `Card/badge_enhance_fill` · `_rim` · `_line` · `_holo` | 강화 육각형 (6-6 색표 적용 중) | 색 사각형 |
| `Card/icon_star` · `icon_lock` · `icon_breakthrough` | 별·잠금·돌파 | 색 사각형 |
| `Currency/currency_*` 12종 | 재화 줄 · 비용 표기 | 색 사각형 |
| `Match/*` 35종 | 경기 화면 전반 | 단색 |
| `Fx/spark` · `star` · `confetti` | 파티클 연출 8종 | 생성된 기본 도형 (교체 가능) |

> 카드 베이스 3종은 작성자 보유분이다 (`경기_UI_명세.md` 3-1 A). 위 경로에 넣으면 카드가 완성된 모습으로 바뀐다.

## 4. Desktop에 넘길 때 쓰는 문장

새 화면 디자인을 Desktop에 요청할 때 아래 틀로 보낸다. CLI가 이 문서를 갱신한다.

```
베이스볼 매니저 — <화면 이름> 디자인 요청

· 기준: 1080×1920 · 세로 고정 · 색 토큰은 경기_UI_명세.md 6-2, 원칙은 6-1
· 구현 파일: Assets/Scripts/UI/Screens/<파일>.cs (좌표를 1:1로 옮긴다)
· 화면에 들어가는 실제 데이터: <이 문서 2장의 "데이터 출처" 열>
· 필요한 것: 좌표가 적힌 보드 + 신규 PNG 목록(파일명·크기·9슬라이스 여부·틴트 기준)
· 금지: 텍스트를 PNG에 굽지 않기 · 레이어 합치지 않기 · 팀 컬러 굽지 않기
```

## 5. 검증 방식 (CLI)

Unity를 켜지 않고 다음을 돌린다. 화면이 실제로 어떻게 보이는지는 작성자가 ▶로 확인한다.

| 하니스 | 대상 | 현재 |
| --- | --- | --- |
| `harness` (net9.0) | `Assets/Scripts/**` 전체 컴파일 + 런타임 검증 | **PASS 101 / FAIL 0** |
| `apicheck` (netstandard2.1 · C# 9) | Unity와 같은 API 표면 | 통과 |

런타임 검증에는 **관전 경로 22건**(새 게임 → 뽑기 → 라인업 → 일정 → 타석 전진 → 하루 확정 → 박스스코어)과
**화면 데이터 경로 30건**(표시 정보 · 필터 · 뽑기 instanceId · 강화 · 훈련 · 돌파 · 분해 · 조합 · 제작 비용 · 라인업 슬롯 · 색 변환),
**연출 코어 14건**(트윈 진행값 · 완료 1회 · 지연 · 취소 · 이징 양 끝 · 파티클 프리셋 8종)이 포함된다.
